博客主题最容易做砸的地方不是功能,是颜色。颜色一多,页面就开始吵。

## 三层,不是两层

大多数主题把"深色模式"当成第二层:一套浅色变量,一套深色变量,来回替换。这在只有一种语义色的时候够用,
一旦需要表达"涨 / 跌"这种方向性语义,就会开始打架 —— 深色下哪个红更重?哪个绿更亮?

`blog-theme` 把它拆成三层:

1. **主题自身颜色** —— 纸面底色、墨色层级、强调色。跟涨跌无关,只跟"这是个什么网站"有关。
2. **配色方案** —— 回答"涨是哪个颜色、跌是哪个颜色",并且各给一套浅色 / 深色取值。
3. **外观** —— 浅色 / 深色 / 跟随系统。

第 2 层不关心第 3 层当前是什么状态,它只负责声明两个方向的取值;第 3 层决定取哪一套。两者在 CSS 里通过
自定义属性的回退值接合:

```css
:root        { --up: var(--up-light, var(--ink-3)); }
[data-theme="dark"] { --up: var(--up-dark, var(--ink-3)); }
```

于是加一个配色方案只需要在配置里写四行:

```toml
[params.theme.schemes.ocean]
  label = "Ocean"
  up = ["#0f7b8a", "#3fb6c9"]
  down = ["#a4512c", "#d99060"]
```

## 正文为什么是 17px / 1.8

窄屏上 16px 加 1.5 的行高,中文长段落会糊成一片;18px 在桌面端又太懒散。17px 配 1.8 是折中,
配合 760px 的栏宽,一行大约 42 个字符 —— 接近眼睛一次扫视的舒适上限。

标题行高压到 1.25 到 1.3,因为标题不需要行与行之间的呼吸;正文行高放到 1.8,长段落才不挤。

## 一个细节

切换外观时用 View Transitions API 做 200ms 交叉淡入,`prefers-reduced-motion` 下直接跳过。
首屏用一个内联同步脚本读取 `localStorage`,所以不会出现"先白后黑"的闪烁。
